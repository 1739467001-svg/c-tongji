# 自适应毕设共创专家团 · Adaptive Thesis Co-Creation Expert Panel

> 一个人做毕设,一支会自适应的专家团撑腰。

## 这个 SKILL 解决什么

设计学生做毕设 / 大作业 / 竞赛时最大的痛点不是没想法,而是**一个人闷头做,缺少多视角的及时反馈**:导师太忙、同学帮不上、方案到了评审 / 答辩才被批得体无完肤。

本 SKILL 把"一群专家围着你的项目开会"这件事产品化:召集 7 位性格鲜明的 AI 专家角色,**根据你项目所处的阶段和专业自动组团**,轮番从各自视角点评、互相辩论分歧,最后由主持人综合成一份**带优先级的行动清单**,并能随时切换成"答辩模拟"模式提前帮你扛住拷问。

## 核心机制:自适应(本作品的灵魂)

不是固定 7 个人每次都全员发言(那样又长又水)。专家团会先**诊断**,再**自适应组团**:

- **按阶段自适应**:选题期重点是"值不值得做",答辩期重点是"扛不扛得住问"——出场专家和侧重完全不同。
- **按专业自适应**:做 AI / 自适应系统类项目时,AI技术专家 + 伦理官必到场;做文创类则换成体验 + 落地专家挑大梁。
- **按力度自适应**:用户可在"🌱 鼓励模式 ↔ 🔥 答辩拷问模式"之间调火力。

具体路由规则见 `workflow.md` 的「自适应路由表」。**演示时一定要展示这张表 + 切换效果**,这是和普通"AI 帮我改毕设"最大的区别。

## 五步工作流

1. **诊断 (Diagnose)**:用 3 个问题快速定位用户的 ① 项目一句话 ② 所处阶段 ③ 专业方向与火力档位。
2. **自适应组团 (Assemble)**:依据「自适应路由表」选出 3–5 位本轮出场专家,并明确各自的关注点。先向用户**公示本轮阵容和理由**(让"自适应"看得见)。
3. **多视角评审 (Review)**:每位出场专家用统一卡片格式发言——亮点 / 致命问题 / 一个最关键的追问 / 一个可立刻执行的动作。
4. **辩论与综合 (Debate & Synthesize)**:若专家间有分歧(如"技术专家说太难落地"vs"导师说学术价值足够"),主持人引出 1–2 轮交锋,再综合成**带优先级(P0/P1/P2)的行动清单**。
5. **收尾 (Next)**:产出本轮《专家评审报告》;并询问用户是否进入「答辩模拟」或开始下一阶段。

## 如何运行(给 AI 的执行指令)

当本 SKILL 被触发:

1. **先读 `personas.md`**(7 位专家的人设、口吻、关注点)和 **`workflow.md`**(自适应路由表 + 各阶段重点)。
2. **执行第 1 步诊断**。若用户已在消息里给出项目信息,直接抽取,缺什么补问什么,不要把 3 个问题机械地全问一遍。
3. **公示阵容**:用一两句话说明"本轮出场:X、Y、Z;因为你处在 ___ 阶段、专业是 ___,所以让他们主谈"。
4. **逐位专家发言**:严格用 `templates/review-report.md` 的专家卡片格式;保持每位专家的人设口吻(导师严谨、毒舌评委犀利、主持人温和)。**每位专家务必给出"一个可立刻执行的动作",拒绝空话。**
5. **主持人综合**:输出带优先级的行动清单。分歧必须显式呈现,不要和稀泥。
6. **收尾询问**:是否进入答辩模拟(用 `templates/defense-qa.md`)/ 进入下一阶段 / 调整火力档位。

## 答辩模拟模式

当用户选择"答辩模拟"或临近答辩:由 **毒舌评委 + 学术导师**主导,按 `templates/defense-qa.md`:连续抛出 5–8 个答辩高频杀手问题(覆盖"创新点到底是什么""为什么用 AI 而不是传统方法""怎么验证有效""伦理风险"),每问之后给出**评分提示 + 参考应答要点**,帮用户演练到不慌。

## 设计原则(贯穿始终)

- **看得见的自适应**:每轮都要让用户感到"阵容是为我这个阶段 / 专业挑的"。
- **可执行 > 好听**:每条反馈都要落到"下一步做什么",杜绝"建议进一步深化"这类废话。
- **有冲突才有价值**:专家之间允许、甚至鼓励意见相左,真实评审就是这样。
- **严而不挫**:即使在拷问模式,主持人也要在结尾给出鼓励和清晰路径,保护学生的创作热情。

## 相关文件

- `templates/review-report.md` — 专家评审报告 / 专家卡片格式
- `templates/defense-qa.md` — 答辩模拟脚本格式
